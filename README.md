# מעקב מחירים יומי – טרקלין חשמל מול המתחרים

כל בוקר הבוט עובר על **כל המוצרים באתר טרקלין חשמל**, מחפש כל מוצר (לפי דגם היצרן) אצל
מחסני חשמל, KSP, א.ל.מ, אייבורי, באג, ביג אלקטריק ולאסט פרייס, ושולח לך מייל עם:

- **איפה המתחרים זולים יותר מטרקלין** ובכמה
- **עליות וירידות מחיר** מאז הריצה הקודמת – בטרקלין ואצל כל מתחרה
- **מבצעים**: מחיר מחוק, אחוז הנחה, מחיר מועדון, מתנות וכו'
- **מצב האתרים**: אם אתר כלשהו לא נקרא היום, תדע על זה
- **קובץ אקסל מצורף** עם ההשוואה המלאה, כל מוצר בשורה, קישורים לכל עמוד מוצר

הכול רץ בענן של GitHub, בחינם, בלי שהמחשב שלך צריך להיות דלוק.

---

## התקנה (פעם אחת, כ-20 דקות)

### 1. פתיחת חשבון ומאגר ב-GitHub
1. נרשמים ב-[github.com](https://github.com) (חינם).
2. לוחצים על **+** למעלה ← **New repository**.
3. שם: למשל `price-monitor`.
4. **Public או Private?**
   - **Public (מומלץ)** – הרצה יומית בחינם וללא הגבלה. הקוד ונתוני המחירים (מחירים ציבוריים מהאתרים) גלויים לכל מי שמגיע לכתובת. הסיסמה וכתובת המייל **לא** גלויות – הן נשמרות כ"סודות".
   - **Private** – הכול פרטי, אבל GitHub נותן 2,000 דקות הרצה בחודש בחינם. ריצה מלאה של כל הקטלוג לוקחת בערך שעה–שעתיים וחצי, כך שריצה **יומית** כנראה תחרוג מהמכסה. אפשר לבחור Private ולהריץ **כל יומיים** (ראו "שינוי השעה והתדירות" למטה).
5. **Create repository**.

### 2. העלאת הקבצים
1. מחלצים את קובץ ה-ZIP שקיבלת למחשב.
2. במאגר החדש לוחצים **uploading an existing file** (או **Add file ← Upload files**).
3. גוררים לחלון **את כל התוכן של התיקייה `price-monitor`** (לא את התיקייה עצמה) ← **Commit changes**.

> ⚠️ **שימו לב לתיקייה `.github`** – במק ובווינדוס תיקיות שמתחילות בנקודה מוסתרות, ולכן לפעמים לא עולות.
> אחרי ההעלאה בודקים שקיימת במאגר התיקייה `.github/workflows`. אם לא:
> **Add file ← Create new file**, בשם הקובץ כותבים בדיוק `.github/workflows/daily-report.yml`,
> מדביקים את התוכן של הקובץ `daily-report.yml` מה-ZIP ← **Commit changes**.

### 3. סיסמת אפליקציה ב-Gmail (כדי שהבוט יוכל לשלוח מייל)
מומלץ לפתוח כתובת Gmail נפרדת לבוט (למשל `myprices.bot@gmail.com`), אבל אפשר גם להשתמש בקיימת.
1. בחשבון הגוגל של כתובת השליחה: [myaccount.google.com/security](https://myaccount.google.com/security) ← להפעיל **אימות דו-שלבי** (חובה).
2. נכנסים ל-[myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords), נותנים שם (למשל "price monitor") ← **Create**.
3. מעתיקים את הקוד בן 16 התווים. גוגל מציגה אותו פעם אחת בלבד.

### 4. הזנת ההגדרות כ"סודות" ב-GitHub
במאגר: **Settings ← Secrets and variables ← Actions ← New repository secret**, ומוסיפים שלושה:

| שם הסוד (Name) | מה לכתוב (Secret) |
|---|---|
| `SMTP_USER` | כתובת ה-Gmail ששולחת, למשל `myprices.bot@gmail.com` |
| `SMTP_PASSWORD` | הקוד בן 16 התווים מהשלב הקודם |
| `EMAIL_TO` | לאן לשלוח את הדוח. כמה כתובות – מפרידים בפסיק |

### 5. בדיקת המייל (דקה)
1. לשונית **Actions** במאגר. אם מופיעה הודעה על הפעלת Workflows – מאשרים.
2. בצד: **דוח מחירים יומי** ← **Run workflow** ← בשדה "מה להריץ" בוחרים **test-email** ← **Run workflow**.
3. תוך כדקה אמור להגיע מייל לדוגמה עם אקסל מצורף (המחירים בו מומצאים, רק להמחשה).
   לא הגיע? בודקים בספאם, ואז נכנסים לריצה ב-Actions ורואים את הודעת השגיאה (בדרך כלל סיסמת אפליקציה שהועתקה לא נכון).

### 6. ריצת ניסיון עם נתונים אמיתיים (כ-15 דקות)
**Run workflow** ← "מה להריץ": **run**, ובשדה המספר כותבים **30** ← **Run workflow**.
הבוט ייקח 30 מוצרים אקראיים מטרקלין, יחפש אותם אצל כל המתחרים וישלח מייל אמיתי.
ריצת ניסיון לא נשמרת בהיסטוריה, כך שהיא לא משבשת את ההשוואות היומיות.

### 7. זהו
מעכשיו הבוט רץ לבד כל בוקר. **הריצה המלאה הראשונה היא הארוכה ביותר** – היא מחפשת כל מוצר בכל אתר,
ויכולה לקחת כמה שעות (אם היא לא מספיקה הכול, היא שולחת את מה שנאסף והריצה הבאה משלימה).
מהריצה השנייה הבוט כבר זוכר איפה כל מוצר נמצא, והריצות מהירות יותר. עליות וירידות מחיר יופיעו החל מהמייל השני.

## מה יש בקובץ האקסל

| גיליון | מה יש בו |
|---|---|
| **סיכום** | מספרים כלליים, ומצב כל חנות: כמה מוצרים נמצאו, בכמה היא זולה/יקרה מטרקלין, הפרש ממוצע |
| **השוואה מלאה** | כל מוצר של טרקלין בשורה, ולכל מתחרה: מחיר, הפרש מטרקלין, שינוי מאתמול, מבצע. אדום = המתחרה זול יותר, ירוק = יקר יותר, צהוב = הזול ביותר בשוק. לחיצה על מחיר פותחת את עמוד המוצר |
| **שינויי מחיר** | כל העליות והירידות מאז הריצה הקודמת, ממוינות לפי גודל השינוי |
| **אירועים** | מבצע חדש, מבצע שהסתיים, מוצר שאזל או חזר למלאי |
| **מבצעים** | כל המבצעים הפעילים בכל האתרים, כולל אחוז הנחה ופרטי המבצע |
| **מתחרים זולים יותר** | המוצרים שבהם מתחרה זול מטרקלין, ממוינים לפי הפער בשקלים |

**איך מתבצעת ההתאמה בין אתרים?** לפי **דגם היצרן** (למשל `GR-728B`), ולא לפי שם המוצר.
כל התאמה נבדקת: הבוט נכנס לעמוד המוצר אצל המתחרה ומוודא שהדגם באמת מופיע שם.
לפעמים אותו מוצר נמכר בקוד שונה במעט (למשל `UE75U8000FUXIL` מול `UE75U8000HUXIL`) –
מחיר כזה מוצג ב**אפור נטוי** עם ההערה "דגם דומה", ולא נכלל בחישוב "הכי זול בשוק", כדי שלא יטעה.

היסטוריית כל שינויי המחיר נשמרת לאורך זמן בקובץ `data/price_changes.csv` במאגר (נפתח באקסל).

## אם אתר מסומן "⚠ לא נקרא"

זה אומר שהאתר חסם את הגישה האוטומטית באותו יום, או שינה את המבנה שלו. שאר האתרים ממשיכים לעבוד כרגיל,
והבוט ינסה את האתר שוב בריצה הבאה.

אם זה חוזר כמה ימים ברצף:
1. **Actions** ← **Run workflow** ← "מה להריץ": **calibrate** ← **Run workflow** (כמה דקות).
2. בסוף הריצה, למטה בעמוד שלה, תחת **Artifacts**, מורידים את הקובץ `report-...`.
3. בתוכו, בתיקייה `debug`, יש צילומי HTML של מה שכל אתר החזיר. שולחים את הקובץ ל-Claude (או למתכנת),
   ואפשר יהיה לכוונן את האתר ב-`config.yaml` (שדות `price_css`, `search_templates`).

כדי לכבות אתר זמנית: ב-`config.yaml` (עריכה ישירות ב-GitHub עם אייקון העיפרון) משנים אצלו `enabled: true` ל-`enabled: false`.

## שינויים נפוצים

**שינוי השעה והתדירות** – בקובץ `.github/workflows/daily-report.yml`, בשורה `cron: "17 3 * * *"`.
השעה היא לפי UTC (שעון ישראל פחות 2 בחורף, פחות 3 בקיץ). דוגמאות:
- `"17 3 * * *"` – כל יום ב-03:17 UTC (ברירת המחדל, המייל מגיע בבוקר)
- `"17 3 */2 * *"` – כל יומיים
- `"17 3 * * 0-4"` – ימים א'–ה' בלבד

**הוספה או הסרה של מתחרה** – בקובץ `config.yaml`, ברשימת `stores`. מתחרה חדש מוסיפים עם `type: generic`
וכתובת האתר ב-`base_url`; הבוט מנסה לגלות לבד איך מחפשים באתר.

**הנמענים** – מעדכנים את הסוד `EMAIL_TO` (Settings ← Secrets and variables ← Actions).

**כמה שורות בגוף המייל** – `top_rows_in_email` ב-`config.yaml` (הדוח המלא תמיד באקסל).

## הערות
- הבוט פונה לכל אתר בקצב איטי (בערך בקשה בשנייה), כדי לא להעמיס על האתרים.
- חלק מהאתרים אוסרים בתנאי השימוש שלהם איסוף נתונים אוטומטי. כדאי לבדוק את התנאים של האתרים לפני השימוש.
- ריצה שנמשכת יותר מ-5 שעות ו-20 דקות נעצרת בצורה מסודרת והדוח יוצא עם מה שנאסף, עם הערה על כך.
- GitHub משבית ריצות מתוזמנות במאגר ציבורי שאין בו פעילות 60 יום. הבוט שומר נתונים במאגר כל יום, כך שזה לא אמור לקרות; אם בכל זאת – בלשונית Actions יופיע כפתור להפעלה מחדש.
